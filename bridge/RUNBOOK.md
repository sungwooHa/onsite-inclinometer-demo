# 온사이트 센서 브리지 — 운영 가이드 (RUNBOOK)

> 실제 현장에서 ESP32(MIDAS_ONSITE_SENSOR)를 맥에 블루투스로 붙여 데모를 돌리는 사람이
> 그대로 따라 하는 문서. 명령은 **`bridge/` 폴더 안에서** 실행한다.

## 한 줄 원리

**"연결"은 센서가 아니라 맥에서 브리지를 실행하는 순간 성립한다.**
센서 전원만 켜는 걸로는 절대 안 붙는다. 맥이 포트를 열어야 데이터가 온다.

```bash
cd "/Users/hsw0312/workspace/02 lab/esp32-inclinometer-demo/bridge"
```

---

## 1. 시작 — 매번 이 한 줄

```bash
./connect_and_run.sh              # 실전: 실제 API 전송
./connect_and_run.sh --monitor    # 확인용: 수신만, 전송 안 함 (리허설 추천)
```

스크립트가 알아서 `unpair → pair → connect → 포트 생길 때까지 대기 → 브리지 실행`을 한다.

**성공 신호 (이게 보이면 끝):**
```
[BT] 포트 노드 확인 (...) — 브리지 실행
[RX] {"event":"BT_CONNECTED", ...}        ← 연결 완료
[RX] {"event":"STATE_CHANGED", ...}       ← 센서 기울이면 실시간으로 뜸
```

멈추려면 `Ctrl+C`.

---

## 2. 안 붙을 때 — 위에서부터 순서대로

1. **같은 명령을 한 번 더 실행.**
   첫 시도가 `No such file ... /dev/cu.*` 같은 에러로 죽을 때가 있다(BT 타이밍). 재실행하면 대개 붙는다.

2. **중복 브리지 정리 후 재실행.**
   ```bash
   pgrep -fl bridge.py      # 뭔가 떠 있으면
   pkill -f bridge.py       # 모두 정리하고
   ./connect_and_run.sh --monitor   # 다시 실행
   ```
   포트는 **한 프로세스만** 열 수 있다. 이전에 띄운 브리지가 살아 있으면 새로 못 붙는다.

3. **센서 완전 리셋 후 재실행.**
   전원(USB) **뽑고 10초** 기다렸다가 → 다시 꽂고 **5초 부팅** → 위 명령 재실행.
   (빠르게 깜빡이지 말 것. 완전히 껐다 켜야 BT 상태가 비워진다.)

4. **그래도 안 되면 맥 블루투스도 리셋.**
   ```bash
   blueutil --power 0 && sleep 3 && blueutil --power 1
   ```
   (또는 시스템설정 > 블루투스 껐다 켜기) → 센서 리셋 → 명령 재실행.

---

## 3. 센서 전원이 끊겼다 들어왔을 때 (제일 흔한 함정)

브리지를 켜둔 채 센서 전원이 빠지면, **브리지는 옛 연결에 멈춘 채로 남는다.**
화면이 안 움직이고 새 `[RX]`가 안 뜨면 = 멈춘 것. 센서를 다시 켜도 **자동으로 안 붙는다.**

> **할 일:** `Ctrl+C`로 브리지 멈춤 → 센서 켜진 것 확인 → `./connect_and_run.sh ...` 재실행.

---

## 4. 종료

`Ctrl+C`. 백그라운드로 돌렸다면 `pkill -f bridge.py`.
**브리지를 남기지 말 것** — 다음에 켤 때 포트를 두고 충돌한다.

---

## 🚫 절대 하지 말 것

- **보드 버튼 누르기** — 짧게=BT 재시작, 길게=페어링 삭제. 연결이 즉시 깨진다.
- **macOS 설정에서 수동 "연결" 클릭** — SPP(데이터 채널)가 안 열려 "연결됨→바로 끊김". 맥에 "연결 안 됨"으로 보여도 정상이다.
- **브리지 2개 동시 실행** — 포트 1개 = 프로세스 1개.
- **센서 전원만 껐다 켜고 붙길 기다리기** — 맥에서 브리지를 다시 실행해야 한다.

## 모드 (`./connect_and_run.sh` 뒤에 붙이는 옵션)

| 명령 | 동작 |
|------|------|
| `./connect_and_run.sh` | **실제 API POST** (진짜 데모) |
| `./connect_and_run.sh --monitor` | 수신만 출력, **전송 안 함** (연결 확인·리허설) |
| `./connect_and_run.sh --dry-run` | 보낼 데이터만 출력, **전송 안 함** |

## 부록 — 증상 → 원인 (참고용)

- **`No such file ... /dev/cu.*` 로 죽음** → BT 포트 생성 타이밍. **재실행**하면 대개 해결.
- **포트는 열렸는데 데이터가 0** (`시리얼 연결:`까지만 찍히고 조용) → SPP 재부착 실패. **재실행**(풀사이클)이 해결.
- **`BT_CONNECTED` 뒤 조용함** → 정상이다. 센서가 안 움직이면 이벤트가 없다. 기울이면 `STATE_CHANGED`가 뜬다.
- **`blueutil 미설치`** → `brew install blueutil`.
